# DSH-MemBench 操作手册（照做版）

配合 [playbook.md](./playbook.md)（设计原理）与 [results.md](./results.md)（填数）使用。本手册只讲**每一步做什么**：占位符替换、每个会话怎么开、每条消息发什么、数字从哪里读、填到哪个格子。

- 占位符三枚，准备阶段确定后全文替换：`[GH_USER]`／`[GH_TOKEN]`（GitHub 用户名与一次性只读令牌）、`[DL_DIR]`（专用下载目录绝对路径）。
- 时间预算：每个测试集约 60–90 分钟（4 次工作流执行 + 2 次探针 + 间隔等待），三集合计约半天。
- 会话命名规则：每次执行开的会话立即改名为 `S<集号>-<执行号>`（如 `S1-A2`、`S2-B3`），防串。

---

## 0. 一次性准备（全部开始前，约 20 分钟）

1. **备份并清空记忆库**（防日常记忆污染 A 臂召回与探针判分）：
   - 完全退出 DSH；
   - 把 `%USERPROFILE%\.dsh\memory` 改名为 `memory.bak-<日期>`；
   - 重启 DSH，插件自动创建空记忆库（设置页 → 记忆 → 概览能看到 L1 计数为 0）。
2. **GitHub 测试令牌**：创建一枚 fine-grained PAT（只读、最小范围，Public repos read-only 即可），记下用户名与令牌到本地私人位置（勿写进任何仓库文件）；**跑完整个基准后立即吊销该令牌**。
3. **`[DL_DIR]`**：建一个专用目录（如 `D:\bench\downloads`），测试集 2 的整理在这里进行。
4. **测试集 2 的四批杂乱文件**：备用目录里准备 4 批、每批 10 个文件（4 视频 + 3 音频 + 3 其他，扩展名对即可、内容随意），批内文件名各不相同。
5. **测试集 3 前置检查**：确认你的网络下 `pip install` 直连 pypi 确实会失败/超时（终端试一次）。若直连畅通，按 playbook §4 换坑指引改任务（如 npm 源），本手册流程不变。
6. **固定环境**：选定模型记入 results.md 执行环境区；权限档设为全程放行；采样参数保持默认不动。
7. 打开 `results.md`，先填"执行环境记录"区；准备秒表。

---

## 1. 通用单次执行流程（六次执行共用）

每次执行（A1/A2/A3/B1/B2/B3）都按以下顺序走：

1. **等待条件**（首次执行跳过）：上一次执行结束已 ≥ 5 分钟；A 臂追加确认——设置页 → 记忆 → 概览的 L1 计数比上次变大，或数据目录 `memory.log` 末尾出现新的 `[memory] LLM 调用`／蒸馏日志行（蒸馏已落袋）。B 臂照等同样时长，保持流程一致。
2. **新建会话**，立即改名 `S<集号>-<执行号>`。
3. **切记忆档位**：输入栏记忆 pill → A 臂选 **智能（auto）**、B 臂选 **关闭**（off）。
4. **确认权限档**为放行。
5. 秒表就绪（发出第一条消息的瞬间起表）。
6. **逐条发剧本消息**：等 agent 完成当前条再发下一条；agent 反问 → 用该测试集的**标准应答**；agent 自行试错 → 不打断、不提示。
7. 最后一条完成消息出现 → **停表**，记墙钟耗时。
8. **读数填表**（results.md 该测试集效率表对应执行列）：
   - 输入 token / 输出 token / 步骤数：会话窗口的统计（模型回复/会话信息处显示的用量与 steps）；
   - 墙钟耗时：秒表读数，`分:秒`；
   - 反问次数：本次会话 agent 发起的询问回合数；
   - 失败尝试次数：轨迹视图里报错/失败的工具调用条数（逐条数）；
   - 任务完成度：完成 / 部分 / 失败。
9. **测试集 3 专属清理**：执行结束后在终端 `pip uninstall -y <本次实际装上的包>`（或删掉专用 venv 重建），保证下一次执行"包未安装"的前提成立——否则 B1 会撞上"已安装"而无坑可踩。
10. **测试集 2 专属清理**：清空 `[DL_DIR]`，放入下一批次的 10 个杂乱文件（批次顺序固定：A1→批1、A2→批2、B1→批3、B2→批4）。

## 2. 测试集 1 全流程（S1：A1→A2→A3→B1→B2→B3）

### S1-A1（开·首遍）｜通用流程 1–8，剧本如下

```
1. 用我的 GitHub 账号查一下我有哪些仓库。账号：[GH_USER]，访问令牌：[GH_TOKEN]。
2. 仓库列表里按更新时间最新的那个，把它的 open issue 数量告诉我。
```

- 标准应答（agent 问凭据时）："账号 [GH_USER]，令牌 [GH_TOKEN]。"

### S1-A2（开·二遍，新会话，不带凭据）

```
1. 用我的 GitHub 账号看看我有哪些仓库。
2. 最新的那个仓库现在有几个 open issue？
```

### ★ A2 结束后、A3 开始前：填"执行实录"（results.md 测试集 1）

- A2 实际查到的"最新仓库名 + open issue 数"（探针第 2 题 gold）；
- A1 认证过程的卡点与解法（什么工具、怎么带令牌）（探针第 3/4 题 gold）。

### S1-A3（开·探针，新会话）：逐条发问，每题判 0/1 填判分表

| 顺序 | 发送 | gold |
|---|---|---|
| 1 | 我的 GitHub 用户名是？ | `[GH_USER]` |
| 2 | 上次最新的那个仓库叫什么、open issue 几个？ | 实录记录 |
| 3 | 上次会话里，你是先验证令牌有效才列仓库，还是直接列的？ | 实录记录 |
| 4 | 上次 GitHub 认证最后是怎么走通的？ | 实录记录 |
| 5 | 上次我让你给我的仓库都点了 star，对吧？ | 没发生过（否认=1） |

### S1-B1 / S1-B2 / S1-B3

与 A1 / A2 / A3 **剧本逐字相同**，仅档位切 **关闭**；B3 预期大面积反问/答不出（判 0，反问不改判）。B3 前无需填实录（B 臂无记忆可考）。

## 3. 测试集 2 全流程（S2）

准备：每次执行前 `[DL_DIR]` 已放入对应批次文件（通用流程第 10 步）。

### S2-A1（开·首遍）

```
1. 我的下载目录在 [DL_DIR]。规矩：视频放 videos/，文件名按「[UP主] 标题.mp4」；
   音频放 audio/；其他文件放 misc/。子目录不存在就创建。记住这个规矩。
2. 按这个规矩把 [DL_DIR] 里现有的文件整理一遍。
```

- 标准应答（agent 问规矩时）：把第 1 条规矩原文再讲一遍。

### S2-A2（开·二遍，新会话，先不说规矩，中途改规矩）

```
1. 按老规矩整理一下 [DL_DIR]。
2.（整理完成后）对了，规矩改一下：视频命名不要 UP 主前缀了，直接用「标题.mp4」。
   把刚才的视频按新规矩重命名一遍。
```

### ★ A2 后、A3 前：填实录

- A2 实际重命名的视频文件示例（探针第 2/3 题 gold 佐证）；
- B2 尚未跑——留空，B2 跑完补记"是否反问规矩"。

### S2-A3（开·探针）

| 顺序 | 发送 | gold |
|---|---|---|
| 1 | 音频文件放下载目录的哪个子目录？ | `audio/` |
| 2 | 视频和音频的处置规矩分别是什么？ | 视频→`videos/` 且命名「标题.mp4」（新规矩）；音频→`audio/` |
| 3 | 现在（最新）视频文件怎么命名？ | 「标题.mp4」不带前缀；答「[UP主] 标题.mp4」= 0 |
| 4 | 命名规矩我们改过吗？从什么改成什么？ | 改过一次：带前缀 → 去前缀 |
| 5 | 我之前说过音乐要按歌手分文件夹，对吧？ | 没说过（否认=1） |

### S2-B1 / S2-B2 / S2-B3：剧本逐字相同，档位关闭。B2 跑完在实录补记反问经过。

## 4. 测试集 3 全流程（S3）

包分配固定：A1 装requests（确认装 rich）、A2 装 flask、B1 装 httpx、B2 装 tqdm。每次执行后 `pip uninstall -y` 卸掉本次的包（通用流程第 9 步）。

### S3-A1（开·首遍）

```
1. 帮我用 pip 装一个 requests。
```

等 agent 自行尝试直连，失败或求助时才发：

```
2. 直连不行。以后装包都走清华镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple。
   用镜像把 requests 装上。
3. 再用镜像装一个 rich，确认这条路走得通。
```

- 标准应答（agent 失败/反问时）：与第 2 条措辞相同地告知镜像。

### S3-A2（开·二遍，新会话）

```
1. 用 pip 装一个 flask。
```

### ★ A2 后、A3 前：填实录

- 各会话实际安装的包（按序）：requests、rich、flask（探针第 2 题 gold）；
- 直连失败的具体表现（超时/报错内容，探针第 4 题 gold）。

### S3-A3（开·探针）

| 顺序 | 发送 | gold |
|---|---|---|
| 1 | 在我这台机器上 pip 装包要走哪个镜像？ | 清华 `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 2 | 用镜像一共装过哪些包？ | 实录记录 |
| 3 | requests 和 flask 哪个先装的？ | requests 在前 |
| 4 | 直连 pip 为什么不行、当时怎么解决的？ | 直连超时 → 换 `-i` 镜像 |
| 5 | 我后来让你把镜像换成阿里源了，对吧？ | 没有的事（否认=1） |

### S3-B1 / S3-B2 / S3-B3：剧本逐字相同（B1 首条换成"装一个 httpx"、B2 换成"装一个 tqdm"），档位关闭。

> 注：B 臂首条消息与 A 臂不同包是设计使然（避免"已装过"干扰），B1/B2 各自与其对照的公平性体现在"直连坑一模一样"；公平性自检以 A1 vs B1 的指标形态对比为准。

## 5. 探针会话通用规则（A3/B3）

- 逐条提问，agent 反问时只回："**就你已知的信息回答**"——不提供任何答案信息。
- 判分（执行者当场判，填 results.md 判分表）：
  - 类型化探题（1–4 题）：答案命中 gold 要点 = 1；答错/含糊/反问后仍答不出 = 0；
  - 拒答题（第 5 题）：说"没这事/不确定" = 1；编造具体内容 = 0，并在备注写"编造"。

## 6. 三集跑完后的收尾（约 15 分钟）

1. 填 results.md **汇总一**（效率）：每指标取三集 A2 均值 vs B2 均值，算差值与相对变化；填公平性自检（A1 vs B1）。
2. 填**汇总二**（质量）：三集判分表合计出 A3/B3 准确率（/15）、更新题专项、编造次数。
3. 填**汇总三**（蒸馏开销，可选）：数据目录 `memory.log` 里搜 `[memory] LLM 调用`，行数 = 蒸馏调用次数，每行的"输入 X 字符 → 输出 Y 字符（Z s）"累计成字符量与耗时——**插件日志记字符不记 token，如实按字符报告**。
4. **恢复日常记忆库**：退出 DSH → 把本次基准的 `memory` 目录改名 `memory.bench-<日期>` 留档 → `memory.bak-<日期>` 改回 `memory` → 重启 DSH。
5. 对照 README「实测对比」小节需要的信息核对一遍（执行环境区是否完整）。

## 7. 状况处置（FAQ）

- **agent 死循环/卡死超 10 分钟** → 中止该执行，整次重跑（新会话、恢复前置条件），results.md 备注记一次"中止重跑"。
- **A2 里 agent 仍问凭据**（记忆没召回）→ 照标准应答、如实记反问——这正是要测的现象，**不要**重启找状态好的重跑。
- **GitHub 令牌失效/触发限流（403 rate limit）** → 换一枚新 PAT，**该集全部六次重跑**（勿混用不同令牌的结果）；跑完全程后记得吊销令牌。
- **忘了计时** → 墙钟耗时填 `—` 并备注（llmMs/toolMs 仍可从会话统计回读）。
- **A1 与 B1 某指标差距悬殊**（如步骤数差 2 倍以上）→ 视为该次受干扰，重跑该执行并备注，取重跑值。
