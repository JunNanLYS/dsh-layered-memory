# 学习曲线基准（Learning-Curve Benchmark）

一套**真机手动执行**的对比基准：同一工作流在**新会话**中执行两遍，对比"开记忆"与"关记忆"的第二遍表现——量化记忆插件让 Agent"长记性"的程度。

- 执行者：仓库作者本人（真人操作 DSH Web）。
- 指标：手动录入（见 [results.md](./results.md)）。
- 结果与方法论摘要随 README「实测对比」小节发布。

---

## 1. 实验设计

### 1.1 核心叙事

记忆的价值不在第一次——第一次开不开记忆都要试错。价值在**第二次**：新会话里，开记忆的 Agent 召回上次上下文，不再询问登录信息、不再走验证过的死路，直取可行路径；关记忆的 Agent 每次都从零试错，不长记性。

### 1.2 执行矩阵（每个测试集 4 次执行）

| 执行 | 记忆档位 | 会话 | 度量意义 |
|---|---|---|---|
| A1 | auto（开） | 新会话 | 学习成本基线，应与 B1 大致相当（公平性自检） |
| A2 | auto（开） | **新会话** | 记忆收益 = A1 → A2 的降幅 |
| B1 | off（关） | 新会话 | 关臂基线 |
| B2 | off（关） | 新会话 | 验证"不长记性"，应与 B1 大致相当 |

**核心对比是 A2 vs B2**（第二遍，开 vs 关）；A1 ≈ B1 是公平性检查，两者差距过大说明该次执行受干扰，重跑该执行。

### 1.3 控制变量

- 同机、同网络、同一 DSH 版本、同一模型与采样参数（DSH 默认），一个测试集的 4 次执行尽量同一天内完成。
- 权限档位全程一致（建议统一放行，避免审批弹窗污染耗时）。
- 每次执行都开**全新会话**；A 臂会话档位设 `auto`，B 臂设 `off`（输入栏记忆 pill 切换）。
- **A1 结束后等闲置蒸馏落袋再开 A2**：间隔 ≥ 5 分钟（默认 `idleSeconds=300` 的闲置兜底触发），或从记忆日志确认 L1 已写入。B 臂同样间隔，保持流程一致。
- 执行顺序固定 **A1 → A2 → B1 → B2**。练习效应（执行者与模型环境越跑越熟）使后跑的 B2 偏快，会**缩小** A2 vs B2 差距——即实测数字对记忆收益是**保守估计**，此偏误方向在 README 方法论中声明。

### 1.4 用户侧行为规则（被问即答）

- 四次执行的用户输入**逐字照剧本**，不主动复述背景。
- Agent 反问时（凭据、规矩、镜像地址等）按各测试集的**标准应答**作答——真实用户行为：问就再讲一遍，不问就省事。反问本身即记忆价值的体现，如实计入"反问次数"。
- Agent 自行试错时不打断、不提示，直到它完成任务或明确求助。

## 2. 测试集 1：凭据与流程（登录 B 站 → 热门榜 → 下载）

押注记忆类型：**凭据事实 + 已验证流程**（L1 事实 / L2 场景）。

准备：专用测试账号一个（下文占位符 `[TEST_ACCOUNT]` / `[TEST_PASSWORD]`，执行时代入；**仓库内永不出现真实凭据**），浏览器工具可用。

### 会话 1（A1、B1 逐字相同）

```
1. 帮我登录B站。账号：[TEST_ACCOUNT]，密码：[TEST_PASSWORD]。
2. 登录好了的话，列出当前热门榜前 10 视频的标题和 UP 主。
3. 把热门第一的视频下载到默认下载目录。
```

### 会话 2（A2、B2 逐字相同，新会话，不带凭据）

```
1. 帮我登录B站。
2. 列出当前热门前 10。
3. 下载热门第一的视频。
```

- 标准应答（仅当 agent 反问凭据时）："账号 [TEST_ACCOUNT]，密码 [TEST_PASSWORD]。"
- 记忆依赖点：凭据、登录可行路径（上次怎么走通的）、下载方法。
- 预期：A2 不问凭据、直走 A1 验证过的路径；B2 问凭据 + 重新试错（扫码、找入口、下载 URL 反复）。

## 3. 测试集 2：用户偏好（下载目录的规矩）

押注记忆类型：**个人偏好**（L1 事实 / L3 画像）。

准备：下载目录预先放置若干杂乱文件（若干视频、音频、其他文件混合；三测试集内不复用同一批文件，避免"上次整理过"干扰——B 臂每次执行前恢复原始乱序快照，A2 恢复为"与 A1 结束时等价的乱序快照"再整理另一批）。

> 快照规则简化版：每臂每次执行都换一批**同规模同构成**的新杂乱文件（如各 10 个：4 视频 / 3 音频 / 3 其他），文件名不同但形态相同。这样无需恢复快照，也避免跨执行污染。

### 会话 1（A1、B1 逐字相同）

```
1. 我的下载目录规矩：视频放 videos/，文件名按「[UP主] 标题.mp4」；音频放 audio/；
   其他文件放 misc/。子目录不存在就创建。记住这个规矩。
2. 按这个规矩把下载目录里现有的文件整理一遍。
```

### 会话 2（A2、B2 逐字相同，新会话，不说规矩内容）

```
1. 按老规矩整理一下下载目录。
```

- 标准应答（仅当 agent 问"什么规矩"时）：把会话 1 第 1 条的规矩原文**再讲一遍**——多花的那一轮口舌就是记忆缺失的真实代价，如实计入。
- 记忆依赖点：目录去向 + 命名格式（细节错一个就算没记全，如漏掉 `[UP主]` 前缀）。
- 预期：A2 直接召回规矩并整理；B2 反问后重教，或自作主张简化命名。

## 4. 测试集 3：可行路径（pip 装包走镜像）

押注记忆类型：**环境约束 + 已验证参数**（L1 事实 / L2 场景）。

准备：统一用 `pip install --user`（或同一专用 venv），四次执行安装的包**各不相同**（requests → rich → flask → httpx 之类），避免"已装过"干扰。

### 会话 1（A1、B1 逐字相同）

```
1. 帮我用 pip 装一个 requests。
```

等待 agent 自行尝试直连（超时/慢/失败后可能反问或放弃）。当它失败或求助时：

```
2. 直连不行。以后装包都走清华镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple。
   用镜像把 requests 装上。
3. 再用镜像装一个 rich，确认这条路走得通。
```

### 会话 2（A2、B2 逐字相同，新会话）

```
1. 用 pip 装一个 flask。
```

- 标准应答（仅当 agent 失败/反问时）：与会话 1 第 2 条措辞相同地告知镜像地址。
- 注意：若你的网络直连 pypi 本来就快，A1/B1 无坑可踩、设计失效——换一个你环境下真实存在"直连不通、需绕行"的路径（如 npm 源、git clone 走代理、某 API 需特定 header），剧本结构不变。
- 记忆依赖点：镜像参数（记住 = 直接带 `-i` 装；没记住 = 先超时一轮再问）。
- 预期：A2 首条命令即带镜像参数；B2 先吃一次直连超时。

## 5. 指标定义（手动录入）

| 指标 | 定义 | 数据来源 |
|---|---|---|
| 输入 / 输出 token | 整个会话累计 | DSH 会话统计（会话窗口的用量显示） |
| 步骤数 | 模型 step 总数（含工具调用步） | DSH 会话统计 / 轨迹视图 |
| 墙钟耗时 | 首条用户消息发出 → 最后一条完成消息 | 执行者掐表 |
| 反问次数 | agent 向用户发起询问的次数（提问回合 / ask 类工具） | 执行者计数 |
| 失败尝试次数 | 返回错误的工具调用（命令报错、登录失败、URL 无效等） | 轨迹视图逐条数 |
| 任务完成度 | 完成 / 部分 / 失败（三档） | 执行者判定 |

录入表与定性备注（"A2 是否未问凭据直接登录"等叙事证据）见 [results.md](./results.md)。

## 6. 局限声明（README 方法论同源）

- 单人、单机、每格单次执行，结果随模型与网络波动，**非确定性**；数字用于展示量级与方向，不构成统计推断。
- 练习效应方向对记忆收益保守（见 §1.3）。
- 剧本作者即插件作者，任务选取天然偏向记忆优势场景；复现者可按本剧本自测。
