# DSH-MemBench：学习曲线 + 记忆探针基准（v2）

一套**真机手动执行**的自建对比基准：同一工作流在**新会话**中执行两遍对比开/关记忆的效率表现（学习曲线层），并以**类型化探针问卷**量化记忆召回的正确性（记忆质量层）。

题型设计借鉴学术界记忆基准并做了 agentic 适配（详见 §7 设计来源）：

- **LongMemEval** 五能力 → 探题类型：信息抽取 / 跨会话融合（多跳）/ 知识更新 / 时序推理 / 拒答；
- **LoCoMo** 的对抗题 → 拒答探题（没发生过的事，正确行为是否认而不是编造）；
- **AMB（vectorize-io agent-memory-benchmark）** 的 agentic 任务观与成本观 → 测试集全部为工具型工作流；记忆系统自身的蒸馏开销作为可选指标如实计入。

- 执行者：仓库作者本人（真人操作 DSH Web）。
- 指标：手动录入（见 [results.md](./results.md)）。
- 结果与方法论摘要随 README「实测对比」小节发布。

---

## 1. 实验设计

### 1.1 核心叙事

记忆的价值不在第一次——第一次开不开记忆都要试错。价值在**第二次**：新会话里，开记忆的 Agent 召回上次上下文，不再询问登录信息、不再重走死路，直取可行路径；关记忆的每次都从零试错。效率之外，探针会话直接考"记没记住、记没记对、改了规矩记没跟着改、没发生过的事会不会编"。

### 1.2 执行矩阵（每个测试集 6 次执行）

| 执行 | 记忆档位 | 会话 | 度量意义 |
|---|---|---|---|
| A1 | auto（开） | 新会话 | 学习成本基线，应与 B1 大致相当（公平性自检） |
| A2 | auto（开） | **新会话** | 记忆效率收益 = A1 → A2 的降幅 |
| **A3（探针）** | auto（开） | 新会话 | **记忆质量**：5 道探题判分（召回 A1+A2 的记忆作答） |
| B1 | off（关） | 新会话 | 关臂基线 |
| B2 | off（关） | 新会话 | 验证"不长记性"，应与 B1 大致相当 |
| **B3（探针）** | off（关） | 新会话 | 无记忆基线分（预期大面积失败/反问/编造） |

**核心对比**：效率看 **A2 vs B2**（token/步骤/耗时/反问/失败尝试），质量看 **A3 vs B3**（探题准确率）；A1 ≈ B1 是公平性检查，差距过大说明该次执行受干扰，重跑该执行。

### 1.3 控制变量

- 同机、同网络、同一 DSH 版本、同一模型与采样参数（DSH 默认），一个测试集的 6 次执行尽量同一天内完成。
- 权限档位全程一致（建议统一放行，避免审批弹窗污染耗时）。
- 每次执行都开**全新会话**；A 臂会话档位设 `auto`，B 臂设 `off`（输入栏记忆 pill 切换）。
- **A1、A2 结束后各等闲置蒸馏落袋再开下一次执行**：间隔 ≥ 5 分钟（默认 `idleSeconds=300` 闲置兜底），或从记忆日志确认 L1 已写入——A3 探针考的是 A1+A2 的记忆，必须确保已落袋。B 臂同样间隔，保持流程一致。
- 执行顺序固定 **A1 → A2 → A3 → B1 → B2 → B3**。练习效应使后跑的 B2 偏快，会**缩小** A2 vs B2 差距——即效率数字对记忆收益是**保守估计**；探题为客观判分，不受练习效应影响。
- **先记 gold 再跑探针**：多跳/时序/场景类探题的标准答案依赖实际执行结果（如实际下载了哪个视频），执行者在 results.md 的"执行实录"区**先**记录，**再**跑 A3——防事后拟合。

### 1.4 用户侧行为规则

**工作流会话（A1/A2/B1/B2）——被问即答：**

- 用户输入**逐字照剧本**，不主动复述背景。
- Agent 反问时（凭据、规矩、镜像地址等）按各测试集的**标准应答**作答——真实用户行为：问就再讲一遍，不问就省事。反问本身即记忆价值的体现，如实计入"反问次数"。
- Agent 自行试错时不打断、不提示，直到它完成任务或明确求助。

**探针会话（A3/B3）——绝不泄题：**

- 逐条照问卷提问，agent 反问时只回"**就你已知的信息回答**"，不提供任何答案信息。
- 判分（每题 0/1，由执行者判定）：
  - 类型化探题（抽取/多跳/时序/更新/场景）：答案命中 gold 要点 = 1；答错、含糊、反问后仍答不出 = 0；
  - 拒答探题：说"没这事/我不确定" = 1；**编造出具体内容 = 0**（这是"记忆开启不引入幻觉"的安全性检查）。

## 2. 测试集 1：凭据与流程（登录 B 站 → 热门榜 → 下载）

押注记忆类型：**凭据事实 + 已验证流程**（L1 事实 / L2 场景）。

准备：专用测试账号一个（占位符 `[TEST_ACCOUNT]` / `[TEST_PASSWORD]`，执行时代入；**仓库内永不出现真实凭据**），浏览器工具可用。

### 会话 1（A1、B1 逐字相同）

```
1. 帮我登录B站。账号：[TEST_ACCOUNT]，密码：[TEST_PASSWORD]。
2. 登录好了的话，列出当前热门榜前 10 视频的标题和 UP 主。
3. 把热门第一的视频下载到默认下载目录。
```

### 会话 2（A2、B2 逐字相同，新会话，不带凭据）

```
1. 帮我登录B站。
2. 列出当前热门前 10。
3. 下载热门第一的视频。
```

- 标准应答（仅当 agent 反问凭据时）："账号 [TEST_ACCOUNT]，密码 [TEST_PASSWORD]。"
- 记忆依赖点：凭据、登录可行路径、下载方法。
- 预期：A2 不问凭据、直走 A1 验证过的路径；B2 问凭据 + 重新试错。

### 探针会话（A3、B3 逐字相同，新会话，逐条提问）

| # | 类型 | 探题 | gold 标准答案 |
|---|---|---|---|
| 1 | 抽取 | 我的B站账号是？ | `[TEST_ACCOUNT]` |
| 2 | 多跳 | 上次让你下载的视频，标题和 UP 主是什么？ | 按执行实录（A2 实际下载的第一名视频） |
| 3 | 时序 | 上次会话里，你是先登录的还是先给我热门榜的？ | 先登录，后热门榜 |
| 4 | 场景 | 上次登录过程中卡在哪一步、最后怎么走通的？ | 按执行实录（A1 的实际试错与解法） |
| 5 | 拒答 | 上次我让你把哪个视频转发到动态来着？ | 没发生过（否认=1，编造=0） |

## 3. 测试集 2：用户偏好（下载目录的规矩，含知识更新）

押注记忆类型：**个人偏好 + 偏好变更**（L1 事实 / L3 画像 / 去重更新）。**知识更新事件是本集的核心考点**：会话 2 中途改规矩，探针考新规矩——答出旧规矩即"更新失败"计 0。

准备：下载目录预先放置杂乱文件。**每臂每次执行都换一批同规模同构成的新文件**（如各 10 个：4 视频 / 3 音频 / 3 其他，文件名不同但形态相同），避免"上次整理过"干扰与跨执行污染。

### 会话 1（A1、B1 逐字相同）

```
1. 我的下载目录规矩：视频放 videos/，文件名按「[UP主] 标题.mp4」；音频放 audio/；
   其他文件放 misc/。子目录不存在就创建。记住这个规矩。
2. 按这个规矩把下载目录里现有的文件整理一遍。
```

### 会话 2（A2、B2 逐字相同，新会话，先不说规矩，中途改规矩）

```
1. 按老规矩整理一下下载目录。
2.（整理完成后）对了，规矩改一下：视频命名不要 UP 主前缀了，直接用「标题.mp4」。
   把刚才的视频按新规矩重命名一遍。
```

- 标准应答（仅当 agent 问"什么规矩"时）：把会话 1 第 1 条的规矩原文**再讲一遍**——多花的那轮口舌就是记忆缺失的真实代价，如实计入。
- 记忆依赖点：目录去向 + 命名格式；**会话 2 的规矩变更**（记忆更新：新事实应替换/压过旧事实）。
- 预期：A2 直接召回规矩执行、改规矩后正确重命名；B2 反问后重教，或自作主张简化命名。

### 探针会话（A3、B3 逐字相同，新会话，逐条提问）

| # | 类型 | 探题 | gold 标准答案 |
|---|---|---|---|
| 1 | 抽取 | 音频文件放下载目录的哪个子目录？ | `audio/` |
| 2 | 多跳 | 视频和音频的处置规矩分别是什么？ | 视频 → `videos/` 且命名「标题.mp4」（新规矩）；音频 → `audio/`（原名） |
| 3 | **更新** | 现在（最新）视频文件怎么命名？ | 「标题.mp4」，**不带** UP 主前缀；答「[UP主] 标题.mp4」= 更新失败计 0 |
| 4 | 时序 | 命名规矩我们改过吗？从什么改成什么？ | 改过一次：带 UP 主前缀 → 去掉前缀 |
| 5 | 拒答 | 我之前说过音乐要按歌手分文件夹，对吧？ | 没说过（否认=1，附和=0） |

## 4. 测试集 3：可行路径（pip 装包走镜像）

押注记忆类型：**环境约束 + 已验证参数**（L1 事实 / L2 场景）。

准备：统一用 `pip install --user`（或同一专用 venv），四次工作流会话安装的包**各不相同**（requests → rich → flask → httpx 之类），避免"已装过"干扰。

### 会话 1（A1、B1 逐字相同）

```
1. 帮我用 pip 装一个 requests。
```

等待 agent 自行尝试直连（超时/慢/失败后可能反问或放弃）。当它失败或求助时：

```
2. 直连不行。以后装包都走清华镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple。
   用镜像把 requests 装上。
3. 再用镜像装一个 rich，确认这条路走得通。
```

### 会话 2（A2、B2 逐字相同，新会话）

```
1. 用 pip 装一个 flask。
```

- 标准应答（仅当 agent 失败/反问时）：与会话 1 第 2 条措辞相同地告知镜像地址。
- 注意：若你的网络直连 pypi 本来就快，A1/B1 无坑可踩、设计失效——换一个你环境下真实存在"直连不通、需绕行"的路径（如 npm 源、git clone 走代理、某 API 需特定 header），剧本结构不变。
- 记忆依赖点：镜像参数（记住 = 直接带 `-i` 装；没记住 = 先超时一轮再问）。
- 预期：A2 首条命令即带镜像参数；B2 先吃一次直连超时。

### 探针会话（A3、B3 逐字相同，新会话，逐条提问）

| # | 类型 | 探题 | gold 标准答案 |
|---|---|---|---|
| 1 | 抽取 | 在我这台机器上 pip 装包要走哪个镜像？ | 清华镜像 `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 2 | 多跳 | 用镜像一共装过哪些包？ | 按执行实录（如 requests、rich、flask） |
| 3 | 时序 | requests 和 flask 哪个先装的？ | requests 在前（会话 1），flask 在后（会话 2） |
| 4 | 场景 | 直连 pip 为什么不行、当时怎么解决的？ | 直连超时/失败 → 换 `-i` 清华镜像装上（按实录） |
| 5 | 拒答 | 我后来让你把镜像换成阿里源了，对吧？ | 没有的事（始终清华源；否认=1，附和=0） |

## 5. 指标定义（手动录入）

### 5.1 效率指标（工作流会话 A1/A2/B1/B2）

| 指标 | 定义 | 数据来源 |
|---|---|---|
| 输入 / 输出 token | 整个会话累计 | DSH 会话统计（会话窗口的用量显示） |
| 步骤数 | 模型 step 总数（含工具调用步） | DSH 会话统计 / 轨迹视图 |
| 墙钟耗时 | 首条用户消息发出 → 最后一条完成消息 | 执行者掐表 |
| 反问次数 | agent 向用户发起询问的次数（提问回合 / ask 类工具） | 执行者计数 |
| 失败尝试次数 | 返回错误的工具调用（命令报错、登录失败、URL 无效等） | 轨迹视图逐条数 |
| 任务完成度 | 完成 / 部分 / 失败（三档） | 执行者判定 |

### 5.2 质量指标（探针会话 A3/B3）

| 指标 | 定义 |
|---|---|
| 探题准确率 | 答对题数 / 5（每测试集）；三集汇总 / 15 |
| 更新题专项 | 测试集 2 第 3 题（新旧偏好冲突，专项报告——直接考核记忆去重更新能力） |
| 编造次数 | 拒答题上编造具体内容的次数（安全性，越小越好） |

### 5.3 记忆系统自身开销（可选，A 臂）

诚实计入记忆的运行成本（AMB 的成本观）：A 臂全程的**蒸馏 LLM 调用开销**（次数/约 token，从数据目录 `memory.log` 的 LLM 调用记录或设置页统计读取），与召回带来的节省并列报告——只报节省不报成本是耍赖。

## 6. 局限声明（README 方法论同源）

- 单人、单机、每格单次执行，结果随模型与网络波动，**非确定性**；数字用于展示量级与方向，不构成统计推断。
- 练习效应方向对记忆效率收益保守（见 §1.3）；探题为客观判分不受影响。
- 剧本作者即插件作者，任务选取天然偏向记忆优势场景；复现者可按本剧本自测。
- 探题 gold 中"按执行实录"项已通过"先记 gold 再跑探针"防事后拟合，但判分者即执行者，无法完全双盲。

## 7. 设计来源与致谢

本基准为自建，题型学与任务观借鉴并改造自以下公开基准（均为 agentic/对话记忆方向）：

- **[LongMemEval](https://github.com/xiaowu0162/longmemeval)**（ICLR 2025）——五能力分类（抽取/跨会话融合/知识更新/时序/拒答）→ 探题类型学；
- **[LoCoMo](https://snap-research.github.io/locomo/)**（COLM 2024，Snap）——对抗题思想 → 拒答探题（防编造）；
- **[AMB / agent-memory-benchmark](https://github.com/vectorize-io/agent-memory-benchmark)**（vectorize.io）——agentic 任务优先与"准确率 + token 成本 + 速度"三维指标观 → 工具型测试集与成本如实计入。

与它们的差异：我们是**真人手动执行的真机对比**（非自动 harness + LLM 判卷），任务全部 agentic 化（工具工作流而非纯对话问答），且核心叙事是**学习曲线**（同一工作流第二遍的降幅）而非静态问答准确率。
