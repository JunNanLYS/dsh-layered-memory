# 规格：记忆优化包——召回消息侧注入 · 蒸馏触发改造 · 分层预算 · FTS 写路径修复

Status: ready-for-agent
Date: 2026-08-18
决策依据: docs/adr/0001（消息侧注入）、docs/adr/0002（FTS 删除策略）、docs/adr/0003（蒸馏触发与会话隔离）；术语见 CONTEXT.md（消息侧注入 / 会话切片 / 捕获档位 / 渐进阈值 / 闲置兜底 / 召回预算）。

## Problem Statement（用户视角）

- 我看不到记忆有没有生效——注入发生在系统提示里，对用户完全不可见；我无法确认"它记住我了"。
- 我没干什么，token 用量却在涨——每轮对话至少触发 1-2 次后台蒸馏调用；还没积累任何记忆时，系统提示里也固定躺着一份工具指南在教模型调用（可能根本没开启的）工具。
- 我的会话之间在互相"串味"——一个会话的消息被当作另一个会话蒸馏时的背景上下文；切换档位后，旧消息可能被错误透镜蒸馏。
- 嵌入服务慢的时候，每一步响应都被拖着等最多 10 秒。
- 我的库大了以后，点一次"重建"要卡好几分钟，且看不出进展中的异常。
- 模型跑偏时单次输出损失没有护栏（全部蒸馏层共用 256k 输出预算）。
- 注入内容没有长度预算，一条异常长的记忆会永久膨胀上下文。

## Solution（用户视角）

记忆召回变成会话流里**可见的注入行**（带插件署名、排在你的消息之前），你一眼能看到记忆生效；注入有预算，超限截断并引导模型用记忆工具查全文。后台蒸馏改为**渐进触发**：首轮即出记忆、随后自动攒批（约 3 轮一次），说完话 5 分钟内未蒸馏的部分自动落袋。所有蒸馏触发按**会话切片**隔离——不同会话、不同档位永不混装，切换档位时旧切片按捕获时档位干净收尾。召回整体最多等 5 秒，超时跳过本轮、绝不拖慢对话。重建的写路径从平方复杂度回到线性。蒸馏输出按层设预算护栏。

## User Stories

### 注入可见性与门控

1. As a dsh 用户, I want 在会话流里看到记忆插件注入的召回行, so that 我能确认记忆功能真的生效了。
2. As a dsh 用户, I want 注入行带插件署名而不是伪装成我的消息, so that 我能区分自己说的话和系统注入的参考。
3. As a 新用户, I want 还没有任何记忆数据时不被注入任何记忆内容, so that 系统提示不被无意义内容占用。
4. As a 关闭了记忆工具的用户, I want 工具指南不再注入, so that 模型不会被引导去调用不存在的工具。
5. As a dsh 用户, I want 工具指南只在"工具开启且确有画像/导航/本轮召回命中"时注入, so that 每步的固定 token 开销有上界。
6. As a dsh 用户, I want 召回内容被明确标注"仅供参考，不代表当前任务进程", so that 模型不会把旧记忆当作当前指令执行。

### 注入预算

7. As a dsh 用户, I want 单条注入记忆超过 500 字符时被截断, so that 异常长记忆不会撑爆上下文。
8. As a dsh 用户, I want 整轮注入总量有 2000 字符上限（低分尾部先丢）, so that 跨轮持久累积的历史有界。
9. As a dsh 用户, I want 截断处附带"可用 memory_search / conversation_search 查看详情"的提示, so that 模型能主动深挖完整记忆。
10. As a 用户, I want 预算可通过配置调整为 0（关闭）, so that 我能按自己的模型成本权衡。
11. As a 助手模型, I want 通过工具路径查到的记忆是全文且不过阈值, so that 截断只发生在注入侧、深挖时能拿到完整信息。

### 注入时机与延迟

12. As a 多步工具循环中的用户, I want 记忆只在轮首注入一次, so that 十步循环不会堆十份重复注入。
13. As a 轮内插话纠偏的用户, I want 插话（新用户消息）后重新检索并注入新方向, so that 纠偏后的回答能用到正确线索。
14. As a 远程嵌入用户, I want 召回整体最多等 5 秒, so that 嵌入服务慢时不拖慢每步响应。
15. As a 远程嵌入用户, I want 召回中的嵌入查询 3 秒没返回就走关键词降级, so that 降级检索还有时间在总预算内完成。
16. As a 本地嵌入用户, I want 本地推理不受额外钳制, so that 模型冷加载后的首次推理不被误杀。
17. As a dsh 用户, I want 召回超时只是静默跳过本轮注入, so that 对话永远不会被记忆功能阻塞。

### 蒸馏触发

18. As a 新用户, I want 第一轮对话就产生记忆, so that 马上体验到"它记住我了"。
19. As a 新用户, I want 前几轮触发频繁、随后逐次放缓（1→2→4→稳态）, so that 新鲜度与调用成本自动平衡。
20. As a 稳态期用户, I want 蒸馏按攒批（约 3 轮/6 条消息）触发, so that 后台调用降到从前的约三分之一。
21. As a 说完就走的用户, I want 会话静默 5 分钟后未蒸馏消息自动落袋, so that 话题尾部不会一直悬着。
22. As a 插件维护者, I want 渐进阈值语义对既有 `minMessages` 配置向后兼容（语义升级为"稳态阈值"）, so that 用户文档平滑迁移。

### 会话隔离

23. As a 多会话并行用户, I want 每个会话的蒸馏切片各自独立, so that A 会话的内容不会成为 B 会话的背景。
24. As a 多会话并行用户, I want 一个会话静默只清它自己的切片, so that 另一个活跃会话的攒批不受影响。
25. As a 重启 dsh 的用户, I want 背景上下文按会话从 L0 现查, so that 重启后抽取质量不降。
26. As a 重启 dsh 的用户, I want 未蒸馏切片带着会话标识持久化, so that 失败重试的残留不会混进别的会话。
27. As a 从旧版本升级的用户, I want 旧格式的未蒸馏缓冲被安全迁移, so that 升级不丢数据。

### 档位切换

28. As a 档位切换用户, I want 切换时旧切片立即按捕获时档位蒸馏, so that 新旧档位永不混装。
29. As a 切到关闭档的用户, I want 已捕获未蒸馏的消息挂起而不是继续蒸馏, so that "停止记忆"的意图被尊重。
30. As a 从关闭档切回的用户, I want 挂起消息按原捕获档位落袋, so that 数据不丢、归属不被改写。

### 输出预算与写路径

31. As a 用户, I want 蒸馏输出按层设预算（抽取 16k / 去重 8k / 场景整合 32k / 画像 16k）, so that 模型跑偏时单次损失有界。
32. As a 开启思考档的用户, I want 分层预算自动放大 4 倍, so that reasoning 不吃光正文预算（历史事故防线）。
33. As a 大库用户, I want 重建/重嵌/导入的写入成本是线性而非平方, so that 重建不再分钟级卡顿。
34. As a 插件维护者, I want FTS 点查预判不改变任何外部可见行为, so that 优化零行为回归。
35. As a 贡献者, I want 否决项（rowid 映射、注入通道兼容开关）在 ADR 里可查, so that 六个月后没人把深思熟虑的决策当 bug "修"回去。

## Implementation Decisions

### A. 召回注入通道（对应 ADR-0001）

- 召回 hook 新增一条 pre-step 监听，**prepend 注册**（先于其它监听器）、先 `await next()` 取基础决策，再在决策消息列表**头部**插入合成消息返回 `{kind:'enter', messages:[注入消息, ...基础消息]}`。
- 合成消息用宿主的"已识别用户消息"构造器创建，来源标识为 `{kind:'plugin', plugin:'memory', form:'recall'}`（`recall` 是宿主语义词汇表中"从其他会话日志捞出的材料"的专值）。
- 触发时机：决策消息列表中存在**新的用户来源消息**（轮首 claim 或 steering 插话）才检索并注入；纯工具步直接透传。
- 注入文本结构：`<relevant-memories>` 包裹 + 原版引导语（"以下是当前对话召回的相关记忆，不代表当前任务进程，仅作为参考"）+ 命中行（沿用 `[type|scene] content` 行格式）。
- 召回预算：单条 500 / 整轮 2000 字符（新配置，0=关闭）；截断后缀 `…（已截断；可用 memory_search 或 conversation_search 查看详情）`；总量超限时按融合排名丢尾部。
- 召回超时：新配置 `recall.timeoutMs` 默认 5000ms，Promise.race 总预算，超时跳过本轮注入并记 warn；远程嵌入 fetch 内层钳制 3000ms（固定值，不新增配置），本地推理路径不钳。
- L0 防污染：零改动——捕获侧既有的"只收用户来源消息"过滤天然排除注入消息。
- 系统提示侧：`memory:recall` 上下文撤除；`memory:profile` 保留画像 + 场景导航 + 工具指南（稳定区）；指南门控三条件 = 工具配置开启 &&（画像非空 ∥ 导航非空 ∥ 本轮召回命中，取自内存召回缓存）。
- 兼容开关：**不提供**。逃生门 = 运行时召回开关 / 会话 off 档 / 版本回退。

### B. 蒸馏触发与调度（对应 ADR-0003）

- 待蒸馏缓冲条目结构增加会话标识；持久化 schema 加字段，旧数据（无字段）归入 legacy 组一次性蒸馏。
- 触发判定从"族桶总数 ≥ 阈值"改为"**该会话切片**条数 ≥ 生效阈值"；命中时只抽取该会话切片。
- 渐进阈值：生效阈值从 1 起步、每次成功抽取后翻倍至稳态值（`minMessages` 语义升级为稳态阈值，默认 1→6）；爬坡状态在族 checkpoint 中记一次（全局爬坡，非按会话）。
- 闲置兜底：单一全局定时器 tick（建议 30s 粒度），扫描各会话最后活动时间，静默 ≥300s（新配置，默认值）且存在切片的会话触发该切片蒸馏；活跃会话切片不动。
- 背景上下文：移除调度器中的全局内存数组；抽取时按会话标识从 L0 检索库现查最近 N 条（新增访问器，走既有会话索引），并按消息 id 剔除切片自身成员（防抽取目标混入背景）。
- 档位切换同步（挂点：会话档位存储的 set() 回调，不开新事件总线）：
  - 非 off 档之间切换 → 该会话切片立即按**捕获档位**蒸馏；
  - 切到 off → 切片挂起不蒸馏；
  - 从 off 切回非 off → 挂起片按捕获档位蒸馏。
- 调度决策（阈值判定 / idle 扫描 / 档位切换动作 / warmup 推进）实现为**纯函数**，与执行（LLM 调用、落盘）分离——这是唯一的新代码边界。

### C. LLM 输出预算

- 各蒸馏层显式传分层 maxTokens：L1 抽取 16k / L1 去重 8k / L2 场景整合 32k / L3 画像 16k（标注"先试跑，按实际截断情况调整"）。
- `reasoningEffort` 为 high/max 时各层预算自动 ×4。
- `llm.maxTokens` 总闸默认 256_000 → 65_536（仍高于全部分层值，作为兜底）。

### D. FTS 写路径（对应 ADR-0002）

- upsert 前的防御性 FTS 删除增加主表存在性点查（主键索引）：行存在才执行 FTS 删除；行不存在（全新增路径——重建/重嵌/导入的主体流量）跳过全扫。
- 不引入 rowid 映射表、不做外部内容表迁移（ADR-0002 否决理由）。

### E. 配置面变化汇总

新增：`recall.maxCharsPerMemory`（默认 500）、`recall.maxTotalRecallChars`（默认 2000）、`recall.timeoutMs`（默认 5000）、idle 静默时长（默认 300s）。
变更默认值：`extract.minMessages` 1→6（语义升级为稳态阈值）、`llm.maxTokens` 256_000→65_536。
不变：`recall.maxResults`、`scoreThreshold`、分族与档位体系、总开关三处门控。

### F. 文档同步义务

- README 中英双语同步（行为变化 + 新配置表）。
- CHANGELOG 记录行为变化（注入通道、默认值）。
- AGENTS.md 架构边界增补新铁律（切片永不跨会话/档位混装；注入消息必须带插件来源与 recall 形态；FTS 防御删除必须先点查）。
- 建议版本号 0.8.0（含行为变化的 minor 版）。

## Testing Decisions

好的测试只断言**外部可见行为**（决策输出、检索结果、持久化往返、配置解析值），不窥探内部实现。全部汇入现有冒烟测试单一入口（纯 assert、无测试框架、不 mock dsh 宿主），沿用四个既有接缝：

- **S1 fake ctx + fake store 缝**（先例：召回 hook 现测）——pre-step 决策：注入消息位置（用户消息之前）、来源标识与形态、标签与引导语、预算截断与后缀、仅新用户消息触发、工具步透传、超时跳过、指南三条件门控。
- **S2 调度纯函数缝**（先例：任务优先级选择纯函数现测）——warmup 阈值推进（1→2→4→6→稳态）、按会话切片选择、idle 扫描（静默达标才清、活跃不动）、档位切换动作表（切走按捕获档位清 / 切 off 挂起 / 切回清挂起）。
- **S3 真实临时库缝**（先例：L0/L1 存储与批量事务现测）——FTS 点查的**行为不变性**（新记录可搜、合并后旧内容不可搜、重建后一致——逐项与现状等价）；按会话取最近消息（含切片剔除）；pending 旧格式迁移（无会话标识 → legacy 组）。
- **S4 配置边界缝**（先例：数值边界现测）——新默认值与边界（500/2000/5000/300s/6/65_536/分层预算与 ×4 规则）。

既有断言回归义务：现有 25 节全部保持通过（尤其捕获缓冲、停机顺序、RPC 端点、档位迁移各节——它们锁定不被本包破坏的行为）。

## Out of Scope

- rowid 映射表 / FTS5 外部内容表迁移（ADR-0002 否决）。
- L1 召回挪入用户消息本体（原版 prependContext 形态，污染原文，弃）。
- 注入通道兼容开关（会谈否决）。
- 按会话各自爬坡的 warmup（复杂度不值）。
- 画像注入侧长度预算（依赖 L3 生成侧的既有长度约束，如需要另立规格）。
- 本轮全量扫描中未纳入共识的其余优化项：client 侧（body 观察器缩围、轮询可见性暂停、stats TTL 缓存、场景 META 头读、列表渲染 memo）、重建影子切换与流式分页读、启动 family 回填版本化、向量检索批量回查与召回倍数合并、嵌入重试与查询缓存、JSONL 保留策略、会话档位 Map 淘汰复杂度等——留给后续独立规格。
- dsh 宿主对 `form:'recall'` 注入行的渲染样式（宿主行为，本插件不写 UI）。

## Further Notes

- 实施顺序建议：D（存储层点查，零行为变化先行）→ B（蒸馏触发改造）→ A（注入通道切换）→ C（预算与超时参数收尾）；每批跑冒烟。
- 风险点：pre-step 消息替换是宿主官方语义（有 dsh-time-context 先例），但**注入消息会进持久会话日志**——上线前在真实 dsh 会话里人工验证一次宿主渲染与捕获过滤（地面真相：数据目录的 L0 JSONL 不应出现注入内容）。
- 分层 maxTokens 数值是"先试跑"状态：上线后观察截断率，必要时在 CHANGELOG 记录调整。
