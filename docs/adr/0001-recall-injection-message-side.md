# 召回记忆走消息侧注入（接受会话内持久累积）

背景：L1 召回原先注入系统提示（每步重建、单槽刷新、不累积）；上游 MemoryCore 的分离
设计是"稳定内容进系统提示、动态召回 prepend 进用户消息"。查证确认 dsh 的
`agent/pre-step` 官方支持替换进入步骤的消息（`PreStepDecision.enter`），且官方插件
`dsh-time-context` 已有"合成消息 + 插件来源"的注入先例。

决定：召回记忆作为带插件来源（`form: 'recall'`，宿主 UI 署名"上下文注入 · memory"
——`source.plugin` 用展示名 memory 而非 cordis id dsh-memory）的独立合成消息进入
对话历史，每轮注入一次，**接受跨轮持久累积**。理由：记忆注入的意义就是持续向模型
提供相关线索、由模型判断是否深挖；相比模型缺乏线索的盲目试错（搜索消耗更多
token），累积是值得的。注入对用户可见，同时构成"记忆生效"的显式提示。

## 考虑过的选项

- 系统提示单槽（原状）：缓存友好、不累积；但注入不可见，模型无法回看历史注入。
- 原版 prepend 进用户消息本体：污染用户原文，需要"缓存干净原文再换回"补丁，放弃。
- 消息侧独立合成消息（选定）：见上。

## 后果

- 系统提示只保留稳定内容（画像 / 场景导航 / 工具指南），动态槽撤除。
- L0 捕获按消息来源跳过注入消息（`source.kind` 过滤已存在），事实源不收录派生内容。
- 注入文本仍以标签包裹，作为模型侧语义边界（"仅供参考，不代表当前任务进程"）
  与助手回显剥离的锚点。
- 旧轮注入随宿主上下文压缩自然淘汰，历史增长有界。
